# 0007: Show current conditions from all household sensors

Date: 2026-08-13

Status: Accepted

## Context

The historical chart dashboard did not provide the at-a-glance readings shown
by MyAcuRite. The household has one Iris and two auxiliary temperature sensors.
The private dashboard response includes all three devices, but the first
integration retained only the Iris. It also includes precise coordinates and
account/device identifiers that K-Weather must not expose.

MyAcuRite's dashboard response does not include the Apple Weather forecast,
cloud, visibility, sunrise/sunset, or moon data displayed elsewhere in its web
interface. Those are not readings generated by the household instruments.

## Decision

Capture every device returned by the single configured MyAcuRite hub. Preserve
the private user-facing sensor names in the private database, but identify
stations internally with generic stable keys (`home`, `sensor_1`, and so on).
Never retain upstream device IDs or location fields.

Add a prominent current-conditions section above the historical filters. For
each household station, show its latest temperature, humidity, dew point,
pressure, and any available Iris wind, feels-like, and rainfall measurements.
Convert numeric wind bearing to a familiar compass abbreviation for display.
Keep historical charts and filters below this section.

Do not represent third-party forecast or astronomy fields as station readings.
A future forecast feature must name and assess its separate public data source.

## Consequences

- The household dashboard now provides the same instrument-generated statistics
  as MyAcuRite without copying its visual design.
- Auxiliary sensor history begins when this change is deployed; older history
  still depends on the private rolling CSV export.
- Sensor names exist only in the private database and authenticated dashboard.
- Device ordering defines generic auxiliary keys. If upstream ordering changes,
  names remain visible but historical series could need a private remapping.
- Forecast and location-service panels remain out of scope for this data source.
